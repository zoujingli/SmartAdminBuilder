# 构建器现有功能

本文梳理独立 Composer 包 `Builder`。它在源码/CI 阶段生成 Phar；数据库快照采集、SFX 多架构拼接和最终审计由仓库外层构建编排继续负责。

## 模块边界

- 消费已经准备好的源码、生产依赖、前端归档、数据库安装包和插件资源。
- 执行文件过滤、Phar 兼容改写、一方源码加固、签名和原子产物替换。
- 不提供后台页面、租户、RBAC，不在生产 Phar 内再次构建自身。

## 已落地能力

| 能力域 | 当前能力 |
| --- | --- |
| 构建入口 | `xadmin:build:phar`，支持项目、入口、目标、版本和挂载参数 |
| 项目收集 | 读取 Composer 元数据、vendor、bin 和 symlink path 包 |
| 文件过滤 | 排除测试、文档、示例、CI、源码前端和非运行时材料 |
| 前端归档 | 校验 `web/dist`，生成运行时 zip，排除动态 `_app.config.js` |
| 安装包校验 | 校验 v2 双 schema、共享数据、前缀、格式和 SHA-256 |
| 插件资源 | 只打入清单声明的 view、language、migration 等资源 |
| Phar 兼容 | AST 改写配置路径、入口挂载和扫描缓存路径 |
| 源码加固 | 一方代码的局部变量、字符串和空白变换，并检测注解兼容风险 |
| 产物发布 | 临时 Phar、CLI stub、SHA-256 签名和原子重命名 |

## 构建主链

1. 检查 `phar.readonly`、vendor 和输入材料。
2. 收集项目、依赖、插件声明资源、前端归档、扫描缓存和发布安装包。
3. 完成路径改写、挂载插入和一方源码加固。
4. 写入随机临时 Phar，创建 CLI stub 并使用 SHA-256 签名。
5. 释放句柄后原子替换正式目标；外层编排再执行 SFX 拼接和产物审计。

## 安全边界

- Builder 只生成 Phar，不能把 Phar 与最终 SFX 混称。
- 数据库安装包由前置流程生成；Builder 只验证和装入，不现场采集数据库。
- 安装包必须是双方言、必要数据模式，拒绝旧单 schema 或 `with_data=true` 全量业务数据。
- 未在 `plugin.json` 声明的插件静态目录不会自动进入产物。
- `_app.config.js` 是运行期配置，不能固化进前端归档。
- 未知第三方依赖不做源码加固，避免破坏反射和元数据合同。
- 源码加固降低可读性，但不是密码学加密或绝对防恢复能力。

## 合理推测

- Builder 将继续保持窄构建核心，快照、SFX 和多架构审计仍由外层编排负责。
- 插件运行资源会继续以显式清单为准，不回退为无差别打包整个插件目录。
- 输入材料缺失或哈希不一致时仍应构建失败，不生成降级制品。

## 当前不应宣传为已实现

- 生产环境内自举构建、在线插件市场或远程热更新。
- Builder 自行生成数据库快照或独立完成所有发布编排。
- 对全部第三方依赖进行无风险源码混淆。

## 主要证据

- `Command.php`、`Provider.php`：构建入口及源码期注册。
- `Support/Builder.php`、`Target.php`、`Package.php`、`Bundle.php`、`Custom.php`。
- `Ast`：Phar 兼容改写与加固访问器。
- `tests/Unit/Builder`：构建加固、输入和发布快照合同。
- `.php-sfx-packer.php`：外层快照、SFX 与审计编排边界。
